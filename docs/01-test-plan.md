# Тест-план — Desktop QA Sandbox (ручное тестирование)

| Поле | Значение |
|------|----------|
| Проект | Тестирование учебного десктопного приложения |
| Объект | `DesktopSandbox.exe` (WinForms, .NET 11) |
| Версия | 1.0, сборка Release |
| Автор | Иван Войтков, intern QA |
| Тип тестирования | **Только ручное**: функциональное, негативное, UI/UX |
| Статус | Выполнено, отчёт закрыт |

## 1. Цель

Проверить три пользовательских сценария приложения вручную, подтвердить наличие заложенных дефектов,
оценить их влияние и подготовить отчёт, пригодный для передачи разработчику.

## 2. Объём

| Модуль | Проверяем |
|--------|-----------|
| Registration | Обязательные поля, e-mail, возраст, пароль/подтверждение, сообщения |
| Orders | Итог, скидка, удаление, сортировка, поиск, сброс |
| Notes | Сохранение в файл, лимит 255 символов, очистка, счётчик |
| Окно | Навигация, минимальный размер, закрытие с несохранёнными данными |

## 3. Вне объёма

- Установка/обновление приложения, работа с реестром.
- Локализация (интерфейс только на английском).
- Нагрузка и многопользовательский режим.
- Сетевое взаимодействие (его нет).
- Совместимость со всеми версиями Windows (проверялась одна конфигурация).

## 4. Подход

1. **Изучение приложения** — пройти все разделы как пользователь, понять заявленные правила.
2. **Тест-кейсы** — подготовить воспроизводимые шаги для позитивных и негативных сценариев.
3. **Ручной прогон** — выполнять кейсы последовательно, фиксировать фактический результат.
4. **Доказательства** — для каждого дефекта сделать снимок экрана или записать точный протокол.
5. **Баг-репорт** — шаги, ожидаемый/фактический результат, severity, причина и рекомендация.

## 6. Тестовые данные

| Поле | Валидные | Невалидные |
|------|----------|------------|
| First/Last name | `QA Tester` | пусто |
| E-mail | `qa.intern@example.com` | `user@domain` |
| Age | `25` | `0`, `-5`, `abc` |
| Password | `Passw0rd!` | `abc123`, несовпадение с подтверждением |
| Заметка | до 255 символов | 300 символов |
| Поиск | `Alpha` | `alpha` (регистр) |

## 7. Критерии входа

- Приложение собирается без ошибок и запускается.
- Все три раздела открываются и отображают элементы управления.

## 8. Критерии выхода

- Пройдены 38 тест-кейсов (PASS/FAIL/N/R).
- Каждый дефект воспроизведён вручную и зафиксирован в каталоге.
- Собраны скриншоты или протоколы для всех дефектов.
- Заполнены сводка и баг-репорты.

## 9. Риски

| Риск | Влияние | Как снижали |
|------|---------|-------------|
| Субъективная оценка «баг или задумка» | Ложные дефекты | Ожидание формулировали по имени поля/подписи и здравому смыслу |
| Окно не в фокусе при снимке | Пустой снимок | Перед снимком окно делалось активным |
| Кириллица/локаль меняют формат чисел | Ложные FAIL | В приложении используется `InvariantCulture` |
| Повтор прогона после перезапуска | Разные начальные данные | Перед кейсами Orders нажимали Reset |
| Часть кейсов не выполнена | Неполное покрытие | Отмечены как N/R, а не выданы за PASS |
