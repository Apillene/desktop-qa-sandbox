# Тест-план — Desktop QA Sandbox

| Поле | Значение |
|------|----------|
| Проект | Тестирование учебного десктопного приложения |
| Объект | `DesktopSandbox.exe` (WinForms, .NET 11) |
| Версия | 1.0, сборка Release |
| Автор | Иван Войтков, intern QA |
| Тип | Функциональное, негативное, UI, accessibility-smoke, автоматизация |
| Статус | Выполнено |

## 1. Цель

Проверить три пользовательских сценария приложения, подтвердить наличие заложенных дефектов,
оценить их влияние и показать, что проверки можно автоматизировать через UI Automation.

## 2. Объём

| Модуль | Проверяем |
|--------|-----------|
| Registration | Обязательные поля, e-mail, возраст, пароль/подтверждение, сообщения |
| Orders | Итог, скидка, удаление, сортировка, поиск, сброс |
| Notes | Сохранение в файл, лимит длины, очистка, счётчик |
| Окно | Навигация, минимальный размер, закрытие с несохранёнными данными |
| Автоматизация | Доступность элементов для UI Automation, устойчивость прогона |

## 3. Вне объёма

- Установка/обновление приложения, работа с реестром.
- Локализация (интерфейс только на английском).
- Нагрузка и многопользовательский режим (приложение однопользовательское).
- Проверка сетевого взаимодействия (его нет).
- Совместимость со всеми версиями Windows (проверялась одна конфигурация).

## 4. Подход

1. **Изучение кода и UI** — понять, какие правила заявлены и какие реально вызываются.
2. **Ручной прогон** — пройти кейсы, зафиксировать фактическое поведение.
3. **Автоматизация** — закрепить воспроизведение через UI Automation, чтобы дефекты не «потерялись».
4. **Регрессионный критерий** — прогон считается успешным, если все ожидаемые дефекты воспроизведены,
   а корректные сценарии проходят.

## 5. Окружение

| Компонент | Значение |
|-----------|----------|
| ОС | Windows 11, 10.0.26300 |
| Runtime | .NET 11 (net11.0-windows) |
| UI | WinForms, Segoe UI 9.5–15 pt |
| Экран | 1920×1080, масштаб 100 % |
| Автоматизация | System.Windows.Automation (UIA), PowerShell 5.1 для скриншотов |
| Файл заметки | `%TEMP%\qa-sandbox-note.txt` |

## 6. Тестовые данные

| Поле | Валидные | Невалидные |
|------|----------|------------|
| First/Last name | `QA Tester` | пусто |
| E-mail | `qa.intern@example.com` | `user@domain` |
| Age | `25` | `0`, `-5`, `abc` |
| Password | `Passw0rd!` | `abc123`, несовпадение с подтверждением |
| Заметка | до 255 символов | 300 символов |
| Поиск | `Alpha` | `alpha` (регистр) |

## 7. Критерии входа

- Приложение собирается без ошибок и запускается.
- Элементы имеют `AutomationId` (иначе автоматизация невозможна).

## 8. Критерии выхода

- Пройдены 38 кейсов (PASS/FAIL/N/R).
- Каждый дефект воспроизведён вручную и автоматически (где применимо).
- Собраны скриншоты и логи.
- Заполнены каталог дефектов и сводка.

## 9. Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| UI Automation не видит элементы кастомных контролов | Автопрогон падает | Добавлены `Name`/`AutomationId`, использованы стандартные контролы |
| Окно не в фокусе | Скриншоты пустые | `PrintWindow` вместо захвата экрана |
| Кириллица/локаль меняют формат чисел | Ложные FAIL | `InvariantCulture` в приложении и проверках |
| Асинхронная перерисовка таблицы | Гонки в проверках | Ожидания с повторами и fallback на подсчёт ячеек |
| Дефект «исправят» | Прогон станет зелёным | Проверки трактуют корректное поведение как неожиданное (FAIL) |
